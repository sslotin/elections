# Независимая проверка ДЭГ

Криптографические проверки на Python: нужны Python ≥3.10, `libgcrypt20`
(для Стрибога) и `tqdm` (для прогресс-бара). При наличии OpenSSL `libcrypto`
арифметика кривой автоматически выполняется в нём — Cython и компилятор не нужны.
Без OpenSSL остаётся реализация на Python.

```sh
python3 -B verify.py /путь/к/выгрузке.zip --workers 16
```

В обычном режиме проверяются GOST- и TeZhu-подписи, форма и ZKP бюллетеней, агрегация ключей и шифротекстов, два Chaum–Pedersen-доказательства расшифровки и соответствие результатам.

`--results-only` пропускает подписи транзакций и доказательства бюллетеней,
но всё равно читает принятые бюллетени, суммирует их шифротексты и проверяет
доказательства расшифровки и опубликованный итог. Это не полная проверка
бюллетеней. `--workers N` запускает `N` рабочих **процессов**, не потоков.

Если независимая полная проверка уже установила, что отдельные бюллетени
недействительны, перечислите их ID транзакций и причины в JSON-файле:

```json
{
  "BASE58_ID_ТРАНЗАКЦИИ": "причина из полной проверки"
}
```

Передайте файл через `--exclude-ballots exclusions.json` вместе с
`--results-only`. Эти бюллетени не попадут в сумму и будут выведены отдельно;
не подменяйте таким списком проверку доказательств.

Коды выхода: `0` — все доступные проверки успешны, `1` — ошибка/нарушение,
`2` — неполная проверка. В `--results-only` код `0` означает успешную проверку
только итогов.

На малой контрольной выгрузке OpenSSL ускоряет доказательства диапазона примерно
в 6 раз относительно прежней версии: около 1,3 мс вместо 8 мс на ячейку.
Это микробенчмарк, не замер полного ЕДГ и не прогноз времени на вашем компьютере.
Память для множества уже учтённых ключей растёт с числом избирателей.

### Перепроверить реализацию

```sh
python3 -B -m unittest discover -s tests -v
python3 -B -m crypto vectors
python3 -B bench.py --no-plot --repeats 100
```

`FEDDEG_EC_BACKEND=python` принудительно выбирает Python,
`FEDDEG_EC_BACKEND=openssl` — OpenSSL с ошибкой при его отсутствии;
по умолчанию используется `auto`. Например, в Linux/macOS/WSL:

```sh
FEDDEG_EC_BACKEND=python python3 -B -m unittest discover -s tests -v
FEDDEG_EC_BACKEND=openssl python3 -B bench.py --no-plot --repeats 100
```

`bench.py --json ПУТЬ` сохраняет замеры и сведения о бэкенде. Без `--no-plot`
нужен ещё `matplotlib`; `--output ПУТЬ` задаёт файл диаграммы.

### Большие выгрузки

Для архива JSONL используйте `verify_archives.py`, а для каталога с нарезанными
JSONL-файлами — `verify_shards.py`. Эти программы читают исходные данные,
сохраняют состояние и журналы отдельно от них и пропускают уже проверенные
неизменённые входы. Например:

```sh
python3 -B verify_shards.py /путь/к/block-dump --state /tmp/feddeg-2026-state.json --workers 16
python3 -B verify_archives.py 2024.zip 2025.zip --state /tmp/feddeg-archives-state.json --workers 16
```

Добавьте `--results-only --exclude-ballots exclusions.json`, если нужна только
проверка итоговой расшифровки с заранее обоснованными исключениями. Для
последовательного запуска 2026, 2024 и 2025 есть `verify_sequence.py`; его
параметры показаны в `python3 -B verify_sequence.py --help`.

В начале каждого криптографического модуля есть ссылки на статьи, формулы,
кодировки, условия отказа и порядок независимой проверки. Общий план — в
[AUDIT.md](AUDIT.md), малые исходные выгрузки — в
[`tests/fixtures`](tests/fixtures/README.md).

**Важно:** обнаружены расхождения PDF и опубликованной реализации в порядке
коэффициентов агрегации ключей и хэшируемых данных доказательства диапазона.
Проверяется профиль реальных выгрузок; расхождения разобраны в комментариях.
Успешный результат не доказывает полноту/подлинность выгрузки, корректность
исполнения блокчейна, допуска избирателей или безопасность протокола целиком.
