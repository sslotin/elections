# Уязвимость проверки числа выбранных кандидатов в бюллетене ДЭГ

*Сергей Слотин, 22 октября 2026*

В протоколе федерального ДЭГ отправленный избирателем «бюллетень» представляется зашифрованным вектором из нулей и единиц, соответствующих проставленным в них галочкам. Эти векторы суммируются (схема шифрования гомоморфна для сложения), и только их сумма расшифровывается и публикуется. Для обеспечения тайны голосования ключ расшифрования не публикуется и индивидуальные голоса не расшифровываются.

Для внешней проверяемости итоговых результатов, для каждой кампании публикуется криптографическое доказательство корректности расшифровки (что из зашифрованной суммы голосов получаются заявленные результаты), а для каждого бюллетеня — что все значения в нем либо нули, либо единицы (чтобы нельзя было указать 101 голос за одного кандидата и -100 за другого), и что сумма голосов за всех кандидатов лежит в определенном промежутке (на некоторых муниципальных выборах, порядка 10% от всех избирательных кампаний, можно проголосовать одновременно за нескольких кандидатов). Доказательства корректности бюллетеня генерируются в браузере избирателя вместе с шифрованием голоса. Сервер их проверяет при подведении результатов, и технические наблюдатели могут независимо проверить их сами.

В реализации доказательства корректного числа отметок допущена ошибка: **привязанная к доказательству сумма не пересчитывается из самих голосов** и никак иначе не проверяется, что позволяет приложить любое не связанное с содержимым бюллетеня доказательство и проставить в самом бюллетене любое число галочек (в том числе проголосовать за всех или ни за кого). Эта ошибка была как в официальной «утилите наблюдателя», так и в серверной части.

Для каждого кандидата все равно проверяется, что голос за него либо ноль, либо единица, и так как недействительных бюллетеней почти нет, то в кампаниях с одной отметкой лишние галочки дадут некорректный итог, где сумма голосов больше числа бюллетеней, и кто-то бы это заметил после подведения результатов. При этом почти во всех муниципальных кампаниях избиратели выбирают не максимум доступных им кандидатов (в среднем ~60%), что позволяет незаметно проголосовать за свыше разрешенного числа кандидатов.

На практике уязвимость вряд ли могла бы существенно повлиять на результаты выборов, однако она подчеркивает необходимость более тщательной проверки реализации и возобновления работы над протоколом ДЭГ.

Недостающую проверку можно проделать ретроспективно: пересчитать сумму для каждого бюллетеня и сверить с указанной в доказательстве. В проверенных мной данных (ЕДГ 2024, 2025 и 2026) расхождений не обнаружено.

Я обнаружил эту уязвимость во время ЕДГ-2026 в процессе разработки [независимой реализации проверок](https://github.com/sslotin/elections/tree/main/feddeg/verification/opensource) и сообщил разработчикам.

## Воспроизведение

Для воспроизведения можно создать бюллетень (`unlinked_sum.csv`), где проставлены две галочки за двух кандидатов, но доказательство приложено от бюллетеня с одной галочкой.

```sh
docker build -t feddeg-official-bugs .. && \
docker build -t feddeg-unlinked-sum . && \
docker run --rm feddeg-unlinked-sum
```

Корректный валидатор должен его отклонить, но официальная утилита его принимает:

```
Проверка ZKP успешна
Итог проверки - РЕЗУЛЬТАТЫ СОВПАДАЮТ.
```
