# Сбор и обработка данных федерального ДЭГ

Код превращает JSONL-дамп блокчейна и метаданные портала в стандартные CSV-таблицы. Обработанные данные старых лет лежат в `data/feddeg`, ссылки на исходные криптографические данные в README.

Из-за роста объема данных в 2026-м году подход стал потоковым. Запишите `dump-chunked.py` на флешку, вставьте её в подготовленный ноутбук в помещении ОП Рф, примонтируйте и выполните в консоли в директории флешки `python dump-chunked.py`. Скрипт начнет писать файл в эту же директорию и сам возобновит работу при остановке. Чтобы перенести на другой компьютер, нажмите ctrl+c чтобы его остоновить и размонтируйте флешку. После чего запустите `parse.py` чтобы нарезать готовые таблицы.

Проект экспериментальный, что-то из этого может не работать.

Старый пайплайн находится в `dump-legacy.py` (`python dump-legacy.py > dump.json`) и `parse-legacy.ipynb`.

## Справочники портала и обновление кэша

Для Python-скриптов нужны Python ≥3.10, `pandas` и `requests`:

```text
python -m pip install pandas requests
python feddeg/parser/parse.py --dump dump.jsonl --out tables --refresh-cache
```

`parse.py` принимает один обычный JSONL-файл. Каталог частей из `dump-chunked.py`
нужно предварительно собрать в такой файл, сохраняя порядок блоков каждого
шарда. Сам парсер исходные файлы не меняет.

Кроме региональных справочников, парсер теперь обходит федеральную иерархию
API v2: выборы → регионы → округа → ТИК → контракты. Список регионов берётся
из статистики выборов: список в `/elections?level=FEDERAL` может быть короче.
Сведения объединяются только по `contractId`, а не по совпадению названий.

Схема существующего `elections.csv` сохранена. Новый `federal_contracts.csv`
дополнительно содержит ID выборов, региона, округа и ТИК, названия, тип
бюллетеня `SINGLE`/`UNION`, `time_offset`, исходное время сводки
`collection_time_local` и признак публикации результатов. Это справочник портала,
поэтому он может содержать контракты, которых ещё нет в дампе. Счётчики берутся
на уровне контракта, без суммирования родительских сводок. Противоречащие друг
другу федеральные привязки одного контракта вызывают ошибку.

- По умолчанию ответы хранятся **300 секунд**; срок меняет `--cache-ttl`.
- `--refresh-cache` игнорирует сохранённые ответы при текущем запуске.
- `--cache-ttl 0` всегда запрашивает свежие ответы.
- `--skip-federal` отключает API v2 для старого или тренировочного портала.
- `--skip-api` по-прежнему строит таблицы без сетевых запросов.

Ключ кэша учитывает адрес сервера, полный запрос и тело POST. Старые файлы
кэша с сокращёнными именами не используются, но не удаляются. Запись атомарная;
повреждённый кэш перечитывается с сервера. Если обновление не удалось, скрипт
выдаёт ошибку, а не подставляет устаревшую сводку.

## Почасовая сверка готовых таблиц

`portal_reports.py` работает с уже готовыми CSV, в том числе опубликованными
архивами после распаковки. Он не скачивает отдельные транзакции.

```text
python feddeg/parser/portal_reports.py --tables tables --out reports --hourly-from 2026-09-18T08:00 --hourly-through 2026-09-18T09:34 --contracts CJ9vdyteoijMZrUXjhfTymUGP6JMvtKppdQ9ZxHKNoPc --refresh-cache
```

Получится `hourly_comparison.csv`: количество строк голосования и выдачи в
дампе, счётчики портала, разницы `дамп − портал` и статус каждого часа.
Без `--contracts` проверяются все контракты из таблиц; начните с небольшой выборки.

**Границы задаёт исследователь по известному покрытию дампа.** Максимальное
время последнего голоса не устанавливает полноту: у тихого контракта новые
голоса могли просто не появиться. Скрипт не пытается вывести покрытие из этого
времени. В примере сравнивается только полный час 08:00–09:00; незавершённый
час 09:00–09:34 исключён. Неполный первый час также исключается.

Времена без часового пояса в CSV и аргументах считаются московскими. Точки
портала обозначают **конец** часа: точка 09:00 сопоставляется с интервалом
`[08:00, 09:00)`. Поле `timeOffset` — сдвиг местного времени относительно МСК;
его вычитают из меток портала. Например, 09:00 при `timeOffset=8` — это 01:00 МСК,
то есть конец московского часа 00:00–01:00.

| Статус | Значение |
|---|---|
| `match` | Оба количества совпали |
| `mismatch` | Есть расхождение; нужно проверить покрытие и семантику операций |
| `unpublished` | Нет полного набора почасовых и накопительных счётчиков |
| `missing_contract` / `missing_point` | В ответе отсутствует контракт или час |
| `unknown_timezone` | Нет пригодного `timeOffset`, сравнение невозможно |
| `not_settled` | Час ещё не закончился или не прошло время ожидания |

По умолчанию после конца часа выдерживается пять минут (`--lag-minutes`).
Это настраиваемый запас, а не гарантия своевременного обновления портала.
Будущие точки с нулевыми значениями, но без накопительных счётчиков, не
считаются подтверждёнными нулями. Неизвестные значения и разницы остаются пустыми.
Отчёт содержит время проверки и заявленные границы дампа.

Сверка показывает согласованность количеств, а не криптографическую корректность
или полноту цепочки. Она не исправляет существующую обработку повторов,
FAIL-операций и откатов в `parse.py`. При расхождении сначала проверьте эти
случаи, границы выгрузки, часовой пояс и задержку сводки.

## Текущая статистика по УИК

```text
python feddeg/parser/portal_reports.py --tables tables --out reports --uiks --contracts CJ9vdyteoijMZrUXjhfTymUGP6JMvtKppdQ9ZxHKNoPc --refresh-cache
```

Новый `portal_uiks.csv` содержит контракт, УИК, `all`, `issued`, опубликованный
процент явки и исходное время сводки каждой страницы. `--uiks` можно совместить
с почасовой сверкой. Метод использует публичный POST-поиск с пагинацией;
повторы УИК, изменение общего количества или оборванный список вызывают ошибку.
Это текущая сводка, не история: между страницами счётчики могут измениться.
Она не заменяет `uiks.csv` со списками избирателей и не привязывает отдельные
голоса к УИК. Если получение страницы не удалось, частичный отчёт не записывается.

## Проверки без сети

```text
python -m unittest discover -s feddeg/parser/tests -v
```

Тесты используют сокращённые публичные ответы портала от 18.09.2026 и
синтетические случаи: федеральные бюллетени, старые региональные справочники,
истечение кэша, временные границы, смещение МСК, будущие точки и пагинация УИК.
Подробности происхождения примеров — в `tests/fixtures/README.md`.
