Обработанные компактные данные федерального дистанционного электронного голосования:

- `edg2024.zip` — 6–8 сентября 2024
- `edg2025.zip` — 12–14 сентября 2025
- `edg2025_training.zip` — тренировка перед ЕДГ 2026
- `edg2026.zip` — финальные данные ЕДГ-2026

**Важно 1:** на ЕДГ-2026 сменилась конфигурация инфраструктуры, которую я заметил только к концу первого дня: до этого скачивались лишь 4 из 7 шардов. Разделение избирательных кампаний по шардам случайное, поэтому все графики и статистические проверки не отличались от реальных ничем, кроме масштаба. Тренировочный архив разобран отдельно; его унифицированная версия описана ниже.

**Важно 2:** в ЕДГ-2026 у избирателей федерального ДЭГ появилась возможность проголосовать на участке бумажным бюллетенем. В связи с этим я изменил формат таблиц: `uiks.csv` с размерами «участков» заменена на событийную таблицу. В каталоге оставлены только четыре компактных ZIP и этот README; прежние архивы сохранены вне репозитория в `/media/sereja/Terabyte/edg/repo-archive-backup-20260927T224148+0300/`.

Таблицы:

- `elections.csv` — регион, кампания и избирательный округ
- `results.csv` — кандидаты и результаты по голосованиям (по округам)
- `ballots.csv` — выдача электронных бюллетеней (по УИК)
- `votes.csv` — погашение бюллетеней (по округам)
- `lists.csv` — УИК, время, число избирателей и тип операции (изначальный список, удаление, восстановление). По заявлению председателя ТИК ДЭГ, досрочно голосующие избиратели тоже удаляются из этого списка (не до конца выяснено, как). Также есть другие причины исключения из списка (некоторые комиссии отправляют списки умерших). Восстановления могут быть когда произошло ошибочное удаление (при этом должна проходить проверка, что избиратели старые, а не новые).

Выдача электронного и бумажного бюллетеня предположительно атомарная: выдадут либо одно, либо другое.

В исходных архивах таблицы соединяются по `contract_id`. Компактные версии для сравнения используют `contract_no`; соответствие исходным ID сохранено в `elections.csv`.

Логически голосования проходят по избирательным округам (чаще всего ТИКам) — одно «реальное» голосование с одинаковыми кандидатами может быть разбито на несколько контрактов. При обработке данных не перепутайте голосование за партсписки и отдельных кандидатов.

Время московское, с точностью до секунды. ZIP-архивы можно читать потоково, не распаковывая их целиком, используя `zipfile` и `pandas.read_csv(..., chunksize=...)`.

## Компактные архивы для сравнения

Все четыре ZIP содержат только пять CSV с одинаковыми столбцами:

| Архив | Контрактов | Бюллетеней | Голосований | Событий списков |
|---|---:|---:|---:|---:|
| `edg2024.zip` | 2 103 | 1 234 722 | 1 226 056 | 17 651 |
| `edg2025.zip` | 3 046 | 2 901 964 | 2 881 290 | 38 113 |
| `edg2025_training.zip` | 2 208 | 453 619 | 436 693 | 54 987 |
| `edg2026.zip` | 5 103 | 12 202 035 | 12 088 374 | 257 733 |

Схема: `elections.csv` — `contract_no, contract_id, region, election, district`; `results.csv` — `contract_no, candidates, results`; `ballots.csv` — `contract_no, uik, timestamp`; `votes.csv` — `contract_no, timestamp`; `lists.csv` — `contract_no, uik, timestamp, count, type`. `contract_no` начинается с 1 и присваивается по порядку строк в `elections.csv` отдельно для каждого архива. Все таблицы соединяются по нему; исходный `contract_id` оставлен в `elections.csv`. Списки `candidates` и `results` — текстовые массивы с попарным соответствием элементов по позиции. Время московское.

`lists.csv` содержит события из блокчейна (`initial`, `restore`, `remove`), а не старую агрегированную таблицу `uiks.csv`. Полные источники и их SHA-256 перечислены выше. Для 2024, 2025 и тренировки 2026 наборы контрактов, векторы результатов и числа операций выдачи/голосования совпали с прежними обработанными архивами; события `lists.csv` согласуются с агрегатами `uiks.csv`.

Названия кампаний, округов и кандидатов для 2024, 2025 и тренировки сохранены из прежних обработанных архивов (резервная копия лежит в каталоге, указанном выше). Аномалия тренировки: у 772 из 2 208 контрактов пусты названия кампании и округа, а список кандидатов пуст во всех 2 208 строках; эти пробелы не заполнялись догадками. В финальном ЕДГ-2026 недостающие названия для 1 880 контрактов Госдумы IX созыва взяты из API `stat.vybory.gov.ru`; метки для 222 контрактов Калининградской области сверены с отчётами протоколов ЦИК (`apps.cikrf.ru`, отчёт 242), а для 46 из них названия кампании и округа взяты из API статистики. Итоги и события голосования взяты из блокчейн-дампов. Признак `signed=true` в API ЦИК отдельно криптографически не проверялся.
